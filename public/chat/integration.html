Integration workspace

Prepare and confirm versioned mappings, process private files and assign mappings to channels.

Checking your session…

Clinical databases are read-only. This version accepts file sources. FHIR delivery uses a separately authorised HTTP API. Uploaded records stay outside the chat and model registry. Storage encryption and retention are managed by your operator.

1. Choose a project

Create a project with pinned dependencies

Project settings are immutable. Choose the actual release, canonical, publisher and exact package versions before creating.

2. Supply the models

Provide the actual FHIR StructureDefinition and, for a route through openEHR or a reverse mapping, the actual openEHR template. A URL or name alone is insufficient. Agent-modelled and externally provided models both require confirmation for this mapping.

3. Prepare and review mapping rules

The agent can draft a mapping using the C# MCP tools. Original user instructions, interpretations, assumptions and synthetic examples belong in the mapping. Resolve all questions before confirmation. Changing the model selection, instructions or rules requires a new mapping version and a new confirmation.

Mapping confirmation does not constitute clinical approval or successful instance validation.

4. Inspect a private source

Upload a private file, or choose an operator-registered source folder. Inspection returns field paths and types without record values. Do not paste patient records into mapping definitions or chat.
