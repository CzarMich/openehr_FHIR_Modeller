Clinical data handling: read-only sources

Clinical databases are strictly read-only. This version accepts file sources. FHIR delivery uses a separately authorised HTTP API. Uploaded records stay outside the chat and model registry. Storage encryption and retention are managed by your operator.

1. Choose a project

Create a project with pinned dependencies

Project settings are immutable. Choose the actual release, canonical, publisher and exact package versions before creating.

2. Supply the models

Provide the actual FHIR StructureDefinition for FHIR output and the actual openEHR template when openEHR is the source or target. A URL or name alone is insufficient. Agent-modelled and externally provided models both require confirmation for this mapping.

3. Prepare and review mapping rules

The agent can draft a mapping using the C# MCP tools. Original user instructions, interpretations, assumptions and synthetic examples belong in the mapping. Resolve all questions before confirmation. Changing the model selection, instructions or rules requires a new mapping version and a new confirmation.

Reuse verified work and save AI calls

Look for existing work before generating a new mapping. Select the actual supplied target models above. Matching checks the source schema, declared source meaning/version, purpose, original user requirements, terminology snapshots and current runtime. Names and column types alone do not establish clinical meaning.

Exact terminology snapshots

Each pin requires canonical, exact version and SHA-256. Use an empty list only when no external terminology snapshots are dependencies; embedded rule dictionaries are already pinned in the mapping. Do not invent versions or hashes.

Corrections create a new version for human confirmation. Reuse does not train a model, create clinical approval, or start a delivery. No patient records belong in this form.

Mapping confirmation does not constitute clinical approval or successful instance validation.

4. Inspect a private source

Upload a private file, or choose an operator-registered source folder. Inspection returns field paths and types without record values. Do not paste patient records into mapping definitions or chat.
