# Worked workflow: neonatal admission draft

This is a modelling demonstration, not a clinical specification. Clinical requirements, archetype selection and terminology require qualified review. No invented clinical node or code should enter a released model.

1. Select filesystem, Git or SharePoint in deployment configuration; the same MCP workflow applies to all. For a shared Designer repository use project `default` on a configured Git review branch as described in [shared Git models](shared-git-models.md). Otherwise create `neonatal-care` with `model_project_create`. Save requirements under `requirements/neonatal-admission.json`, with stable IDs, descriptions, priorities and unresolved questions. Record that birth weight and reflex examination require discovery and clinical review; do not declare coverage yet.
2. Call `ckm_sources`, select a configured CKM, search with `ckm_archetype_search`, and retrieve candidates with `ckm_archetype_get`. Read the returned definition, actual node paths and provenance. Select a COMPOSITION and ENTRY/SECTION/CLUSTER placements only when the source supports the intended use. A missing neonatal reflex candidate remains an explicit modelling gap.
3. Call `template_build_oet` using direct `entries` for a flat draft or `placements` for a parent-first explicit placement tree with exact archetype-relative paths. It returns a draft OET, source provenance and a bounded document check; if the native engine is configured, nested drafts also receive the supported compile-profile check. Slots, inherited constraints, terminology binding and full legacy semantics still require separate review. Save the returned XML, sources and unresolved decisions through `model_artifact_save`.
4. Retrieve the current artifact/revision before edits. A client may propose revised XML using the template design/review prompt and source guides. Run `model_validate` and `model_diff`, then save with `expectedRevision`. A stale revision is rejected. There is no arbitrary native template edit engine in this build.
5. Terminology binding is optional: omit this step when the model has no terminology requirement. For coded fields use explicit local value sets, or discover candidates in an optionally configured terminology system and use `terminology_lookup`, `terminology_validate_code` and bounded `terminology_expand`. Store explicit value-set references and binding records under `terminology/`. Run `terminology_binding_validate`; missing version, node resolution or native preservation remains unresolved. Local demonstration codes use an organisation-specific URI.
6. Persist the explicit requirements graph with `model_traceability_save`: stable requirement IDs, modelling decisions/rationales, exact artifact revisions/hashes, actual constraint anchors and optional binding references. Query `model_traceability_explain` for an element or `model_traceability_requirement` for R-023. Coverage remains a declaration; missing/stale source references and unexecuted native paths remain findings. The legacy `model_requirements_coverage` operation remains available for supplied arrays. Record exclusions with reasons.
7. Draft AQL with the existing design/review prompt and actual template paths. Save it under `aql/`. `model_qa` does not execute AQL or compile OPT and records those missing stages. A CDR is optional and no query results are fabricated.
8. Save structural/terminology diffs, decisions and `terminology_manifest` with the draft. Call `governance_prepare` for its exact revision, then `governance_validate` and `governance_request_review` using the returned audit sequence each time. The installed validation executor records authoritative evidence; uploaded report files cannot replace it. Link the returned event subject, sequence and hash into the requirements graph and retain the graph revision with the review evidence.
9. In `/chat/reviews`, an independent signed-in reviewer inspects the recorded source, validation and history, then confirms a review or request for changes. Clinical approval/publication requires qualified engine evidence and appropriate human roles. Current incomplete validation blocks those transitions; this demonstration is not deployable. See [governance](../GOVERNANCE.md).

After linking exact validation evidence, run `model_project_qa` on the saved revision. Resolve provenance, stale-source and traceability findings before requesting review. Preserve unavailable engine/dependency checks explicitly; a document profile pass cannot qualify neonatal clinical content.

For ADL 2 template sources, use `template_validate`, `template_compile` and `opt_validate`, or `template_compile_project` to save the native OPT with exact source/dependency/compiler evidence. This is separate from the draft OET workflow and does not establish clinical suitability. [Compilation guide](../OPT_COMPILATION.md).
