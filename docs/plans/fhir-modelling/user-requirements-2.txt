  <agent-behaviour>
    A request such as:

      "Create a Patient profile."

    must NOT immediately produce an invented StructureDefinition.

    The agent must retrieve project context and determine:

      FHIR release;
      canonical namespace;
      jurisdiction;
      project dependencies;
      configured knowledge sources;
      existing profiles;
      relevant national profiles;
      relevant international profiles;
      terminology;
      modelling requirements.

    It must then perform reuse analysis.

    The final artifact must have traceable reasons for:

      chosen parent;
      constraints;
      terminology;
      extensions;
      dependencies.

    When important requirements are genuinely absent, the agent may identify explicit
    assumptions.

    When safe defaults are configured at project level, use them without repeatedly
    questioning the user.

    The agent must distinguish between:

      "I found this in an authoritative artifact."

      "I inferred this from the requirements."

      "I generated this constraint."

      "This has been validated."

      "This has not yet been validated."

    Never represent inference as authoritative specification content.
  </agent-behaviour>

  <cross-standard-mapping>

      FHIR profile

        <->

      openEHR path
        <->
      FHIR element path / FHIRPath

      openEHR terminology binding
        <->
      FHIR terminology binding

    Mapping artifacts must have:

      source artifact version;
      source path;
      target artifact;
      target artifact version;
      target path;
      mapping relationship;
      transformation rule where applicable;
      terminology mapping where applicable;

      status;

    Support mapping relationship semantics such as:

      narrower;
      broader;
      transformed;

  </cross-standard-mapping>
